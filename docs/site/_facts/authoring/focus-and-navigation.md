## follow-up

**RESOLVED IN 0.7.0, and this analysis is how.** The branch is gone from box.js and the question is asked in `computeStyle`'s match loop instead, where the rule that failed to match is still in hand: `selectorMatches` gained an `ignoreFocus` parameter, and a `:focus` rule that would have matched but for the attribute now warns, once per rule. The reasoning below is kept because it is what located the fix -- including the three fixtures tried here, which are now the two the test uses.

`packages/layout/src/box.js:296-300` was dead code. The warning

```
css: :focus styles matched <tag> line N but no enclosing element has the focusable
attribute; the delta can never show
```

fires when `focusDeclared` is true and the focus scope is null. `focusDeclared`
(packages/layout/src/css.js:1023) is true only when a matched rule's selector carries
`:focus`, and `compoundMatches` (css.js:192) refuses a `:focus` compound on any element
without the `focusable` attribute. So the matching element is either focusable itself
(scope is its own box id) or a descendant of a focusable ancestor named by an earlier
compound (scope is that ancestor's box id). Either way the scope is non-null.

Tried this session, none of which warned: `.tile:focus` on a non-focusable `.tile`;
`.tile:focus .label` with `.label` under a non-focusable `.tile`; `span:focus` on a
non-focusable `span`. No test in `packages/layout/test/` covers the message, and
`grep -rn "delta can never show"` matches only box.js:299. Either drop the branch, or
make `compoundMatches` match `:focus` on any element and let this warning carry the
diagnosis.
