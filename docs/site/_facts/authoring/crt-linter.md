## follow-up

Not in the drift table, found while verifying:

1. `docs/tutorial-uc3.md` states that without `.row:focus .size` the dim text
   sits on the focused row "at 2.33:1". The compiler reports 2.28:1 for that
   pair. Compiling the tutorial's own `ui/library.html` and `ui/library.css`
   with that one rule removed printed
   `contrast: "--" contrast 2.28:1 < 3:1` six times. The prose number is stale
   and `tools/check-tutorial.py` cannot catch it, because the sentence is not
   inside a ```text block.
2. The focusable form of `overscan` (packages/layout/src/lint.js:277-282) says
   "extends past the action-safe area" while its test is `x + w > canvasW`,
   which is the canvas edge. Action-safe is conventionally a 5% inset inside
   title-safe's 10%, so the message names a rectangle the code never computes.
   A focusable 640px wide on a 640x448 canvas passes; 641px warns.
3. The previewer's `Safe area` button draws a 10% inset
   (packages/baker/ps2ui_bake/serve_page.html:321) and its tooltip says 10%,
   while the `overscan` lint uses 5% (packages/layout/src/lint.js:139-140).
   An author checking a lint against the overlay is looking at a different
   rectangle. Either the overlay should draw the lint's inset, or the lint
   should expose its inset to `/state`.
4. A warning in `ps2ui serve` cannot jump to the command it is about.
   `serve_page.html:521-535` reads `w.command` and treats it as a jump target,
   but `serve.py:380` only ever writes `{screen, text}`, so the branch is
   dead for every same-screen warning. The lints carry no command index today;
   adding one to the IR warning strings would make the existing page code work.
